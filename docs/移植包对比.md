### 安全层的实际能力差距

**能做的**：
- 拆 shell 命令、认出危险命令、按三档分级
- 判断目标路径是否越界（区分沙箱/真机两种场景）
- 出 dry-run 摘要（文字描述，不是真正预演）
- 脱敏审计（内存 200 条）

**做不了的**：
- **不可逆操作前拍快照**——`SnapshotPlan` 只是数据结构，没有真的复制文件
- **执行失败后回滚**
- **同一次会话里改同一个文件两次的冲突处理**（`SnapshotConflictPolicy`）
- **审计持久化**

### 按「缺了会不会出事」排优先级

| 优先级 | 缺口 | 后果 |
|---|---|---|
| **P0** | 文件快照 | 不可逆操作没有后悔药。现在的 `SnapshotPlan` 是个空壳，声明了要备份但没备份 |
| **P1** | Goal/Plan 的 DB 持久化 | App 一重启，进行中的目标全丢，计划表也清空 |
| **P1** | `GOAL_CONTINUATION.md` | 续跑只发一句「继续」，模型不知道自己该干什么，会重复劳动 |
| **P2** | `ProposedPlanParser` 接渲染 | `<proposed_plan>` 现在只是去掉标签，没做成卡片 |
| **P2** | 沙箱工具链一键安装 | 现在要 AI 跑十几条命令，中途网络一抖就断 |
| **P3** | 审计落 DB | 重启后查不到历史操作 |

## 六、下一步建议

**先补 P0（文件快照）**。理由：

安全层现在的行为是**声称要备份但没有备份**——

```kotlin
val snapshot = if (analysis.tier == RiskTier.C_IRREVERSIBLE) {
    SnapshotPlan(
        scope = SnapshotScope.FILES,
        targets = ...,
        required = true,          // ← 声明必须备份
        captureSupported = ...,
        noSnapshotAllowed = false,
    )
} else SnapshotPlan.NONE
```

`required = true` 但没有任何代码去执行这个计划。比「明确说不备份」更糟：用户以为有保险。

**需要写的东西**：
1. `FileSnapshotManager`：复制目标文件到一个按时间戳命名的快照目录
2. `SnapshotRecord` / `SnapshotIndexStore`：记录哪些文件被备份了、路径映射
3. 恢复：从快照目录把文件复制回去
4. 接入 `ToolSafetyCoordinator`：执行前调用，失败就拒绝执行
5. 容量控制：快照目录超过多少就清最旧的

这大概是 400~600 行 Kotlin，加上接入和测试。
